### الف) ۲۴ سند حقوقی جدید (فقط شناسنامه)

این اسناد در فهرست مرجع بودند اما **متن ماده‌به‌مادهٔ آن‌ها در منابع آزاد پروژه موجود نبود**.
به‌جای حذف یا جعل متن، «شناسنامهٔ سند» آن‌ها ساخته شده است:

- عنوان، عنوان کوتاه، دسته موضوعی، سلسله‌مراتب، نوع سند، تاریخ تصویب (در صورت اطمینان)؛
- خلاصه و کلیدواژه؛
- وضعیت «لازم‌الاجرا» و منبع «فهرست مرجع ورودی — متن رسمی: qavanin.ir».

## ۲) چه مواردی از پیش وجود داشت؟

۲۹ عنوان از ۵۳ عنوان فهرست مرجع، از قبل با متن کامل در برنامه بودند و **دوباره اضافه نشدند**:

قانون اساسی، مدنی، مسئولیت مدنی، حمایت خانواده، روابط موجر و مستأجر (۱۳۷۶)، تملک آپارتمان‌ها،
اجرای احکام مدنی، مجازات اسلامی، آیین دادرسی کیفری، اصلاح قانون مبارزه با مواد مخدر، نحوه اجرای
محکومیت‌های مالی، تجارت، اصلاح قسمتی از قانون تجارت، تجارت الکترونیکی، صدور چک، حمایت از حقوق
مصرف‌کنندگان، کار، تأمین اجتماعی، مالیات‌های مستقیم، مالیات بر ارزش افزوده، رسیدگی به تخلفات اداری،
دیوان عدالت اداری، شهرداری، ثبت اسناد و املاک، حمایت حقوق مؤلفان و مصنفان و هنرمندان، حمایت از حقوق
پدیدآورندگان نرم‌افزار، شوراهای حل اختلاف، آیین دادرسی مدنی، تشکیل دادگاه‌های عمومی و انقلاب.

دو هم‌ارزی که نام متفاوتی دارند و در اسکریپت تطبیق به‌صورت صریح ثبت شده است:

| عنوان فهرست مرجع | مدخل موجود در برنامه |
| --- | --- |
| قانون اصلاح قسمتی از قانون تجارت (مواد ۲۱ الی ۹۳) | `commercial-amendment-1347` — لایحه اصلاحی قانون تجارت (شرکت‌های تجارتی) |
| قانون حمایت حقوق مؤلفان و مصنفان و هنرمندان | `authors-rights-law` — قانون حمایت از حقوق مؤلفان، مصنفان و هنرمندان |

## ۵) نحوهٔ اعتبارسنجی

```bash
npm run data:build        # ساخت داده‌ها (۶۴ سند | ۶٬۶۱۸ ماده | ۱۱۹ نهاد)
npm run data:validate     # ساختار، نرمال‌سازی، ۲۵ آزمون صحت متنی، نهادها
npm run registry:verify   # تطبیق فهرست مرجع با داده‌های ساخته‌شده
npx tsc --noEmit          # بررسی نوع‌ها
npx next lint             # بررسی کد
npm run build             # خروجی ایستا شامل ۶۴ صفحه قانون
```

سه لایهٔ اعتبارسنجی:

1. **`data:validate`** — یکتایی شناسه‌ها، فیلدهای الزامی هر سند، انطباق دسته و سطح
   سلسله‌مراتب، نبود حرف عربی/نمایشی، ترتیب شماره مواد، **۲۵ آزمون صحت متنی** روی مواد شاخص،
   و برای نهادها: یکتایی شناسه، هم‌خوانی گروه، وجود عنوان/وضعیت/منبع و انطباق شمار با آمار کاتالوگ.
2. **`registry:verify`** — فهرست مرجع را در برابر کاتالوگِ ساخته‌شده تطبیق می‌دهد و گزارش
   می‌دهد چه چیزی «از پیش موجود»، «افزوده‌شده»، «تکراری» یا «ناموجود» است. تطبیق با چهار
   قانون انجام می‌شود: عنوان دقیق ← هم‌ارزی اعلام‌شده ← زیررشته ← تطبیق واژگانی (با حذف
   واژه‌های stop). خروجی فعلی: `۲۹ از پیش موجود | ۲۴ افزوده‌شده | ۰ ناموجود | ۱۱۹ نهاد منطبق`.
3. **ساخت و بررسی نوع‌ها** — خروجی ایستای Next.js همهٔ ۶۴ صفحهٔ قانون (شامل اسناد
   فقط‌شناسنامه) را تولید می‌کند؛ `tsc` و `next lint` بدون خطا اجرا می‌شوند.
