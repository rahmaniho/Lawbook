# نصب نسخه اشتراکی کتابچه روی cPanel (PHP/MySQL)

این نسخه برای **دامنه یا ساب‌دامنه اختصاصی با ریشه `public_html`** تهیه شده است؛ PHP 8.1+، افزونه PDO MySQL، MySQL 5.7+/MariaDB با InnoDB، Apache 2.4 با mod_rewrite و HTTPS لازم است. Node.js فقط روی رایانه سازنده برای بیلد نیاز است، نه روی هاست. برای نصب در زیرپوشه باید مسیرهای ثابت و تنظیمات نصب جدا تغییر کنند؛ این راهنما نصب در ریشه دامنه است.

## مدل دسترسی

- بازدیدکننده بدون حساب، پیش‌نمایش‌های محدود قراردادها، دو درس، گزیده قوانین و آرای منتخب، یک تمرین و یک محاسبه آموزشی را می‌بیند.
- نسخه کامل فقط پس از ثبت‌نام، پرداخت خارج از سامانه و **تأیید مستقل مدیر** باز می‌شود. ارسال کد پیگیری به تنهایی هیچ دسترسی ایجاد نمی‌کند. درگاه آنلاین در این نسخه وجود ندارد.
- اعتبار طرح به روز است؛ طرح ۳۰روزه الزاماً «یک ماه تقویمی» نیست. تمدید از زمان انقضای اشتراک فعال و برای اشتراک منقضی از زمان تأیید محاسبه می‌شود؛ زمان‌های پنل UTC هستند.
- تمام HTML، JavaScript، فونت‌ها، فایل‌های RSC و JSON دادهٔ نسخه کامل از PHP و پس از بررسی اشتراک همان درخواست ارسال می‌شوند، نه صرفاً با قفل ظاهری رابط کاربری.
- این نسخه **اشتراک حساب کاربری** است، نه قفل سخت‌افزاری/تک‌دستگاه یا لایسنس دائمی. دستگاه‌ها محدود نشده‌اند؛ برای آن سیاست و توسعه جدا لازم است.

## ۱. ساخت بسته

```bash
npm ci
npm run build:licensed
```

خروجی در `build/cpanel/` است و در Git ذخیره نمی‌شود:

```
build/cpanel/
  INSTALL.md
  public_html/             # فقط محتویات این پوشه داخل وب‌روت
    .htaccess
    index.php
  lawbook-private/         # بیرون وب‌روت، کنار public_html
    config.example.php
    policy.php
    schema.sql
    previews.json
    app/                   # خروجی کامل و پولی Next؛ هرگز داخل public_html نگذارید
```

این دستور بیلد تازه با `NEXT_PUBLIC_BASE_PATH=/app` و `NEXT_PUBLIC_LICENSED_DEPLOYMENT=1` می‌سازد. `out/` عادی، `public/`، سورس‌ها یا `.next/` را به هاست عمومی کپی نکنید. بسته با بیلد معمولی GitHub Pages متفاوت است. اگر هاست از LiteSpeed استفاده می‌کند، اجرای قواعد `.htaccess` و رفتار بدون کش را به‌طور واقعی آزمایش کنید.

## ۲. محل آپلود

در File Manager سی‌پنل «نمایش فایل‌های مخفی» را فعال کنید تا `.htaccess` منتقل شود:

```
/home/CPANELUSER/public_html/index.php
/home/CPANELUSER/public_html/.htaccess
/home/CPANELUSER/lawbook-private/config.php
/home/CPANELUSER/lawbook-private/policy.php
/home/CPANELUSER/lawbook-private/previews.json
/home/CPANELUSER/lawbook-private/app/...
```

اگر document root ساب‌دامنه جای دیگری است، متغیر `$private` ابتدای `index.php` باید به پوشه‌ای **بیرون از تمام document rootهای عمومی** اشاره کند. فایل خصوصی فقط برای کاربر اجرای PHP قابل خواندن باشد (معمولاً فایل‌ها ۶۰۰ و پوشه‌ها ۷۰۰؛ با تنظیم واقعی هاست تطبیق دهید). وب‌سرور نباید به `lawbook-private` alias عمومی داشته باشد. نسخه پشتیبان هم عمومی نباشد. فایل‌های قدیمی `index.html`، `data` و `_next` را در وب‌روت باقی نگذارید؛ کنترلر فقط مسیرهای مجاز را پاسخ می‌دهد، اما حذف نسخه قدیمی و کش CDN نیز ضروری است. برای دامنه‌ای که قبلاً PWA داشته، سرویس‌ورکر و کش قدیمی را پاک و ترجیحاً از ساب‌دامنه اختصاصی تازه استفاده کنید.

## ۳. دیتابیس و تنظیمات

1. از MySQL Database Wizard، دیتابیس و کاربر اختصاصی بسازید و دسترسی همان دیتابیس را بدهید؛ حساب root استفاده نشود.
2. `schema.sql` را **یک بار در دیتابیس خالی** از phpMyAdmin وارد کنید. SQL مهاجرت برای دیتابیس موجود نیست.
3. `config.example.php` را در پوشه خصوصی به `config.php` کپی و DSN، نام کاربری و گذرواژه را در هاست وارد کنید؛ اطلاعات واقعی را در چت یا Git نگذارید.
4. مقدار `rate_limit_secret` را حداقل ۳۲ کاراکتر تصادفی بگذارید. تولید محلی:

   ```bash
   php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
   ```

5. `site_name`، `support_contact` و `payment_instructions` را با مشخصات خود تکمیل کنید. کارت بانکی مشتری، CVV2 یا رمز نخواهید. این نسخه آپلود تصویر رسید ندارد؛ فقط کد پیگیری و بررسی مستقل بانکی است.
6. پس از تکمیل هویت فروشنده، شرایط حقوقی و چک‌لیست staging، مقدار `sales_enabled` را `true` کنید؛ به‌صورت پیش‌فرض `false` است و ثبت درخواست خرید مسدود می‌ماند.
7. AutoSSL/HTTPS را فعال کنید. `allow_http_local` در تولید **false** بماند. پشت reverse proxy، HTTPS باید توسط پیکربندی مورداعتماد وب‌سرور به PHP منتقل شود؛ از اعتماد بی‌قید به هدر کاربر خودداری کنید.
8. نمایش خطاهای PHP را در تولید خاموش و error log خصوصی را فعال کنید. PHP session storage باید قابل نوشتن و دور از وب‌روت باشد.

## ۴. ساخت مدیر و طرح‌ها

رمز یا حساب مدیر پیش‌فرض وجود ندارد:

1. در سایت با ایمیل خود ثبت‌نام کنید؛ گذرواژه قوی و یکتا بسازید.
2. شناسه و ایمیل حساب خود را در phpMyAdmin احراز کنید و **فقط همان ردیف** را مدیر کنید:

   ```sql
   UPDATE users SET role = 'admin' WHERE id = YOUR_VERIFIED_USER_ID;
   ```

   عبارت بالا نمونه است؛ شناسه را از ردیف واقعی بگیرید و پیش از اجرا کنترل کنید که یک ردیف انتخاب شده باشد.
3. دوباره وارد شوید و در «مدیریت»، طرح‌های واقعی با مدت روز و قیمت **ریال** بسازید. هیچ قیمت آزمایشی یا طرح فعال پیش‌فرض عرضه نمی‌شود.
4. کاربر پس از پرداخت، طرح و کد پیگیری را ثبت می‌کند؛ مدیر مبلغ، هویت و وصول را مستقل بررسی و سپس تأیید یا رد می‌کند.
5. تأییدها تراکنشی و یک‌بارمصرف‌اند؛ درخواست پرداخت، نام طرح و مبلغ و مدت زمان ثبت را نگه می‌دارد. توقف فروش طرح، درخواست‌های قدیمی را حذف نمی‌کند.
6. لغو اشتراک از پنل ممکن است و در درخواست بعدی فایل و بررسی دوره‌ای برنامه اثر دارد. ثبت عملیات مدیریت در `audit_log` نگهداری می‌شود.

## ۵. آزمون الزامی پیش از فروش

تست‌های سیاست مستقل با `php tests/cpanel-policy.php` اجرا می‌شوند. تست کامل HTTP/MySQL در `tests/cpanel-http.mjs` فقط با دیتابیس خالی و یک‌بارمصرف و متغیر `LAWBOOK_TEST_DATABASE=disposable` قابل اجراست؛ هرگز آن را روی دیتابیس کاربران اجرا نکنید. گردش‌کار `cPanel PHP checks` همین محیط یک‌بارمصرف را می‌سازد.

روی دامنه staging و سپس هاست واقعی بررسی کنید:

- در حالت مهمان، صفحه رایگان باز شود؛ `/app/` به اشتراک برود و لینک مستقیم به یک فایل **واقعی موجود** در `/app/_next/static/...js` و `/app/data/version.json` پاسخ ۴۰۳ بدهد.
- `/app/sw.js` و فایل config، SQL، `.env`، source map و مسیرهای `../` نباید دریافت شوند.
- با ثبت‌نام، بدون تأیید پرداخت، دسترسی کامل باز نشود؛ کاربر عادی حق اجرای عملیات مدیریت نداشته باشد.
- تأیید یک درخواست، اشتراک را باز کند و تأیید مجدد همان درخواست، دوباره زمان اضافه نکند؛ دو مدیر هم‌زمان نیز نباید دوبار تمدید کنند.
- اشتراک فعال با خرید جدید از پایان قبلی تمدید شود؛ انقضا، خروج و لغو دسترسی در تب دیگر را امتحان کنید.
- POST بدون CSRF معتبر رد شود؛ بیش از حد تلاش ورود مسدود شود؛ خطای دیتابیس دسترسی را باز نکند.
- حالت موبایل، فونت، ناوبری `/app`، درخواست‌های RSC، جست‌وجو و دانلود داده با اشتراک فعال را امتحان کنید.
- از دور زدن PHP توسط CDN، کش LiteSpeed یا rule موجود جلوگیری کنید. همه `/app/*` و `index.php` باید از کش عمومی مستثنا باشند و `Cache-Control: no-store` حفظ شود.
- پشتیبان‌گیری و بازیابی دیتابیس و تنظیمات خصوصی را تمرین کنید.

## ۶. محدودیت‌های مهم و الزامات تجاری

- PWA آفلاین در بسته اشتراکی ثبت نمی‌شود؛ بررسی اعتبار در آغاز، تغییر مسیر و حدود هر ۶۰ ثانیه انجام می‌شود. نبود اینترنت قفل ایجاد می‌کند. پایگاه محلی آن از نسخه عادی جداست و هنگام رد اعتبار، محتوای محلی به صورت best-effort پاک می‌شود.
- هیچ وب‌اپی نمی‌تواند متن، اسکرین‌شات، فایل یا نسخه‌ای را که کاربر مجاز قبلاً ذخیره کرده پس بگیرد. این راهکار کنترل تحویل سرور است، **نه DRM مطلق**. یادداشت‌ها و نشانک‌های شخصی حذف نمی‌شوند.
- نسخه عادی برنامه همچنان برای توسعه/استقرار رایگان قابل ساخت است. سورس و محتوایی که از قبل در GitHub یا Pages عمومی منتشر شده، با این تغییر خصوصی نمی‌شود. برای جلوگیری از انتشار عمومی بعدی، repository variable به نام `LICENSED_DEPLOYMENT` با مقدار `true` بسازید؛ سپس Pages قبلی را از تنظیمات GitHub غیرفعال/حذف کنید. Vercel/Netlify و mirrorهای موجود را نیز جدا بررسی کنید. پیش از خصوصی‌کردن مخزن، حقوق دسترسی همکاران را بررسی کنید.
- ایمیل در این نسخه تأیید خودکار و بازیابی رمز خودکار ندارد؛ احراز مالکیت و بازیابی امن حساب نیازمند رویه پشتیبانی مدیر است. برای عرضه عمومی پرترافیک، تأیید ایمیل، بازیابی امن، MFA مدیر، مانیتورینگ و بازبینی امنیت مستقل توصیه می‌شود.
- هویت فروشنده، نشانی و اطلاعات تماس، سیاست انصراف/استرداد، تعهد پشتیبانی، دوره نگهداری اطلاعات و شرایط حقوقی متناسب با محل عرضه را **پیش از ایجاد طرح فروش** در صفحه شرایط و تنظیمات تکمیل کنید. حقوق آمره مصرف‌کننده با متن قراردادی حذف نمی‌شود.
- مجوز بازنشر منابع، محتوا و اجزای ثالث و ادعاهای به‌روز بودن قوانین را جدا بررسی کنید. این تغییر به تنهایی مجوز فروش همه منابع نمی‌دهد.
- گواهی و تست اجرای واقعی MySQL/Apache/SSL روی هاست شما جایگزین تست‌های مخزن نیست؛ تا چک‌لیست نصب روی هاست واقعی اجرا نشده، بسته «آماده فروش تأییدشده» محسوب نمی‌شود.
